# Audit of Project Codebase

This document audits all pipeline components, noting modifications, enhancements, and design rationale across Core, Advanced, and Expert tiers.

## File Audit Summary

| Component | Status | Actions Taken | Rationale |
|---|---|---|---|
| `project/pipeline/config.py` | Kept & Enhanced | Added canonical output paths for hierarchy reconciliation, EV shift, macro lag, what-if scenario, stockouts, event impact estimates, and what-if scenario grid. Added `Unassigned` to canonical regions. Added event forecast rules mapping for EV-052, EV-059, EV-062. | Ensures consistent output management and eliminates untracked string literals across the pipeline. |
| `project/pipeline/load.py` | Kept | Maintained clean data ingest functions with strictly read-only access to `student_data/`. | Strictly honors Ground Rule 1 (raw files immutable). |
| `project/pipeline/audit.py` | Kept | Standardized audit logging format across all cleaning steps. | Ensures full auditability for every data modification per Ground Rule 2. |

| `project/pipeline/clean_train.py` | Enhanced | Deduplicated strictly on `Date, SKU_ID, Region, Customer_Name` by dropping 167 records with conflicting sales channels (Rule T4b), yielding 244,321 clean rows. | `project/pipeline/unconstrained.py` | Enhanced | Reconstructed true demand using requested units from inventory stockouts. Added integer proportional allocation across multiple customers sharing the same Date-SKU-Region key (Rule A2). Identified suspected unlisted stockouts via run-length drops. Exported cleaned stockouts to outputs. | Separates unconstrained market demand from operational supply constraints and guarantees exact unit conservation. |
| `project/pipeline/ordering_cycles.py` | Created | Classified ordering periodicity (monthly, bi-monthly, quarterly, irregular) per customer-SKU series. Flagged churned accounts. Built strictly on historical data without future leakage. | Supports Expert tier customer cycle tracking and dynamic features. |
| `project/pipeline/ev_shift.py` | Created | Measured ICE vs EV sales progression across powertrain types. Evaluated EV adoption index lead-lag cross-correlations and regressions. | Fulfills Expert tier powertrain technological transition modeling. |
| `project/pipeline/structural_breaks.py` | Created | Quantified pre-announcement early buying (EV-030), regional holiday seasonality, and master data lifecycle integrity. | Isolates genuine structural market shocks from baseline trends. |
| `project/pipeline/features.py` | Rewritten | Fixed YoY growth feature calculation. Added customer cycle and intermittency features. Embedded dynamic holiday and event flags. Enforced one-to-one merge with unconstrained demand and asserted zero duplicate series keys. | Eliminates duplicate features and provides rich context for tree-based models without duplicate rows. |
| `project/pipeline/models/lightgbm_model.py` | Rewritten | Implemented early stopping validation with subsequent full-dataset refit. Enforced non-crossing quantile ordering. Configured deterministic parameters (`random_state=42`, `force_row_wise=True`). Removed silent fallbacks. | Maximizes historical data utilization, guarantees valid prediction intervals, and ensures bit-for-bit reproducibility. |
| `project/pipeline/forecast.py` | Rewritten | Implemented recursive multi-step forecasting for horizons 1-19. Added predecessor SKU history inheritance for new launches (`Replaces_SKU`). Applied calibrated event multipliers from `events_calendar.csv` (EV-052 Helios Auto Parts India, EV-059 price elasticity, EV-062 plant shutdown) and exported `event_impact_estimates.csv`. Reconciled hierarchy against independent top-level projections. Generated what-if scenario grid across [-6.0, +6.0] PMI deltas. | Prevents lag feature freeze, eliminates hardcoded strings, ensures top-down hierarchy consistency, and supports scenario planning. |
| `project/pipeline/backtest.py` | Rewritten | Built honest 3-origin rolling backtest (2023-10, 2024-10, 2025-03) with strict temporal training isolation, dynamic feature re-engineering per origin, LightGBM quantile model refits, and 19-month recursive forward evaluation. Exported predictions with `p10, p50, p90` columns to enable empirical interval coverage evaluation. Evaluated against seasonal naive, moving average, and Croston/SBA/TSB baselines on identical test slices. | Provides rigorous, leak-free out-of-sample model verification. |
| `project/pipeline/anomalies.py` | Rewritten | Documented market contractions, early buying, and stockouts with explicit actions. | Complies with the complete decision coverage mandate. |
| `project/pipeline/reports.py` | Rewritten | Documented cleaning rules with full rationale, before and after row counts (244,488 to 244,321). | Clear audit presentation for governance review. |
| `project/run_pipeline.py` | Rewritten | Unified end-to-end execution in one reproducible script with no silent errors or bare exceptions. Connected honest backtesting, what-if scenario grid, and output verification. | Satisfies Ground Rules 4, 5, and 6. |
| `project/app/dashboard.py` | Rewritten | Ensured all data is loaded exclusively from `outputs/`. Fixed filter population so SKU and customer selectors are dynamically populated without empty option warnings. Renamed annualized run-rate metric to explainable 19-month comparison. Connected interactive what-if slider to the precomputed scenario grid. | Satisfies Ground Rules 5 and 7 with clean, robust user experience. |
| `project/tests/test_cleaning_rules.py` | Enhanced | Added unit tests for Unassigned region, S1 BU resolution, YoY feature uniqueness, quantile ordering, hierarchy tolerance, T4b single-row deduplication, A2 stockout allocation exact conservation, backtest prediction columns, absence of hardcoded customer names, new launch inheritance, and what-if zero-delta equality. | Guarantees test coverage for every cleaning rule and model invariant. |
